# Цели Яндекс.Метрики для AZONE AI

Документ фиксирует цели, которые нужно создать в интерфейсе Метрики вручную, и JavaScript-цели, которые отправляются из кода сайта.

## Ручные цели в интерфейсе Метрики

Создать как цели типа «Посещение страницы».

- `contact_page_view`
  - Условие: URL содержит `/contact/`.
  - Где срабатывает: страница заявки.
  - Как проверить: открыть `/contact/?_ym_debug=1`.
  - Тип конверсии: макроконверсия.

- `product_page_view`
  - Условие: URL содержит `/products/`.
  - Где срабатывает: каталог и страницы продуктов.
  - Как проверить: открыть любую страницу `/products/.../?_ym_debug=1`.
  - Тип конверсии: микроконверсия.

- `service_page_view`
  - Условие: URL содержит `/services/`.
  - Где срабатывает: каталог и страницы услуг.
  - Как проверить: открыть любую страницу `/services/.../?_ym_debug=1`.
  - Тип конверсии: микроконверсия.

- `cases_page_view`
  - Условие: URL содержит `/cases/`.
  - Где срабатывает: страница кейсов.
  - Как проверить: открыть `/cases/?_ym_debug=1`.
  - Тип конверсии: микроконверсия.

- `whitepaper_thanks_view`
  - Условие: URL содержит `/whitepaper/thanks/`.
  - Где срабатывает: thank-you страница whitepaper.
  - Как проверить: открыть `/whitepaper/thanks/?_ym_debug=1`.
  - Тип конверсии: макроконверсия.
  - Важно: эта цель должна считаться только правилом посещения страницы в интерфейсе Метрики. JS-событие с таким же именем не отправляется, чтобы не было двойного учёта.

## JavaScript-цели из кода

- `form_submit`
  - Где срабатывает: успешная отправка формы `/contact/`.
  - Как проверить: отправить контактную форму с `?_ym_debug=1`, в консоли должно появиться `Reach goal: form_submit`.
  - Тип конверсии: макроконверсия.

- `form_submit_qualified`
  - Где срабатывает: успешная отправка формы `/contact/`, если заполнены `industry`, `role`, `project_horizon`.
  - Как проверить: заполнить эти три поля и отправить форму.
  - Тип конверсии: макроконверсия.

- `form_error`
  - Где срабатывает: ошибка отправки формы `/contact/`.
  - Как проверить: временно использовать некорректный endpoint в dev-окружении или отключить сеть перед отправкой.
  - Тип конверсии: микроконверсия.

- `consultation_click`
  - Где срабатывает: CTA «Получить консультацию» на странице контактов.
  - Как проверить: кликнуть CTA на `/contact/?_ym_debug=1`.
  - Тип конверсии: микроконверсия.

- `discuss_project_click`
  - Где срабатывает: CTA «Обсудить проект», «Обсудить внедрение», «Обсудить пилот».
  - Как проверить: кликнуть любой из этих CTA.
  - Тип конверсии: микроконверсия.

- `phone_clicked`
  - Где срабатывает: клик по ссылке `tel:`.
  - Как проверить: кликнуть телефон на `/contact/?_ym_debug=1`.
  - Тип конверсии: микроконверсия.

- `email_clicked`
  - Где срабатывает: клик по ссылке `mailto:`.
  - Как проверить: кликнуть email на `/contact/?_ym_debug=1`.
  - Тип конверсии: микроконверсия.

- `presentation_download`
  - Где срабатывает: скачивание `AZONE_AI_presentation.pdf`.
  - Как проверить: кликнуть «Скачать презентацию».
  - Тип конверсии: микроконверсия.

- `whitepaper_download`
  - Где срабатывает: клик по прямой ссылке на whitepaper PDF или кнопке скачивания whitepaper на thank-you странице.
  - Как проверить: кликнуть кнопку скачивания на `/whitepaper/thanks/?_ym_debug=1`.
  - Тип конверсии: макроконверсия.

- `whitepaper_cta_click`
  - Где срабатывает: CTA, который ведёт на форму `/whitepaper/`, но сам не скачивает PDF.
  - Как проверить: кликнуть whitepaper-блок на главной или в блоге.
  - Тип конверсии: микроконверсия.

- `whitepaper_form_submit`
  - Где срабатывает: успешная отправка формы `/whitepaper/`.
  - Как проверить: отправить форму whitepaper.
  - Тип конверсии: макроконверсия.

- `oprosnik_download`
  - Где срабатывает: скачивание опросника.
  - Как проверить: кликнуть «Скачать опросник».
  - Тип конверсии: микроконверсия.

- `demo_request_clicked`
  - Где срабатывает: CTA «Запросить демо» и «Запросить доступ к демо» на страницах продуктов.
  - Как проверить: открыть продукт с демо и кликнуть CTA.
  - Тип конверсии: микроконверсия.

- `calc_pilot_used`
  - Где срабатывает: первое использование калькулятора пилота или CTA после расчёта.
  - Как проверить: изменить параметр калькулятора или кликнуть «Уточнить расчёт».
  - Тип конверсии: микроконверсия.

- `blog_to_product_click`
  - Где срабатывает: переход из статьи блога на продуктовую страницу.
  - Как проверить: открыть статью с блоком связанных продуктов и кликнуть продукт.
  - Тип конверсии: микроконверсия.

- `blog_article_completed`
  - Где срабатывает: статья блога прочитана до 80% и пользователь провёл на странице минимум 60 секунд.
  - Как проверить: открыть статью, ждать 60 секунд, проскроллить ниже 80%.
  - Тип конверсии: микроконверсия.

- `external_link_click`
  - Где срабатывает: переход по внешним ссылкам, включая демо-домены.
  - Как проверить: кликнуть внешнюю ссылку.
  - Тип конверсии: микроконверсия.

- `pdf_download`
  - Где срабатывает: клик по PDF, который не относится к презентации, опроснику или whitepaper.
  - Как проверить: кликнуть любую другую PDF-ссылку.
  - Тип конверсии: микроконверсия.

Дополнительная служебная цель:

- `cases_cta_click`
  - Где срабатывает: CTA «Посмотреть кейсы» в блоке после заявки на `/contact/`.
  - Как проверить: кликнуть CTA.
  - Тип конверсии: микроконверсия.

## Проверка через debug-режим

1. Открыть нужную страницу с параметром `?_ym_debug=1`, например `/contact/?_ym_debug=1`.
2. Открыть консоль браузера.
3. Выполнить действие: клик по CTA, скачивание PDF, отправка формы.
4. В консоли Метрики должно появиться сообщение вида `Reach goal: <goal_name>` или запись о вызове `reachGoal`.
5. Если включён dev-режим сайта, дополнительно можно увидеть сообщения helper'а вида `[YM goal]`.

Метрика не должна блокировать отправку форм: если `window.ym` недоступен или заблокирован расширением, сайт продолжает работать без ошибки.

## Примечания по дублям и селекторам

- Цели типа «Посещение страницы» создаются в интерфейсе Метрики и не дублируются JavaScript-вызовами с тем же именем.
- Для элементов с `data-ym-goal` глобальный обработчик отправляет только явно указанную цель и не запускает дополнительную авто-классификацию ссылки. Поэтому PDF-кнопки с `presentation_download`, `oprosnik_download`, `whitepaper_download` не должны дополнительно отправлять `pdf_download`.
- CTA на форму whitepaper размечаются как `whitepaper_cta_click`, а фактическое скачивание PDF — как `whitepaper_download`. Это предотвращает двойной учёт download-цели в воронке whitepaper.
- Для ссылок без `data-ym-goal` действует авто-классификация: `tel:` → `phone_clicked`, `mailto:` → `email_clicked`, PDF → соответствующая download-цель, внешние URL → `external_link_click`.
- `blog_article_completed` защищён флагом `sent` и отправляется один раз за просмотр страницы.
- `calc_pilot_used` защищён флагом `pilotUsedSent` и отправляется один раз за просмотр калькулятора.
